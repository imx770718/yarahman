# متجر يَارَحْمَنُ يَارَحْمَنُ — Cloudflare Pages

هذا مشروع متجر عربي يعمل على Cloudflare Pages Functions مع قاعدة بيانات Cloudflare D1 وتخزين صور Cloudflare R2. لا يحتاج إلى Bolt أو خدمة بناء مواقع خارجية.

## ما يتضمنه المشروع

- واجهة متجر عربية متجاوبة مع الشعار المرفق.
- عرض المنتجات والأقسام والبحث والسلة.
- إنشاء طلب حقيقي مع التحقق من المخزون واحتساب رسوم منطقة التوصيل.
- قاعدة D1 للعملاء والمنتجات والأقسام والطلبات وتفاصيل الطلبات والعروض والمناطق والإعدادات والصفحات والمدراء وسجل العمليات.
- تسجيل وإنشاء حساب العميل عبر API.
- دخول الإدارة بجلسة موقعة ومحمية، وتخزين كلمات المرور باستخدام PBKDF2.
- إدارة المنتجات والأقسام والطلبات ومناطق التوصيل والعروض والمدراء والإعدادات والصفحات.
- صلاحيات للمدراء الموظفين، وسجل عمليات، ورفع صور إلى R2 عبر API.
- تتبع الطلب عبر API: `/api/track?order_no=...&phone=...` وسجل طلبات العميل عبر `/api/customer/orders` بعد تسجيل الدخول.

## 1) أنشئ موارد Cloudflare

من لوحة Cloudflare أنشئ:
1. مشروع Pages واربطه بمستودع GitHub.
2. قاعدة D1 باسم `yarehman-db`.
3. حاوية R2 باسم `yarehman-images`.

في إعدادات Pages > Settings > Functions > Bindings اربط:
- D1 Database: الاسم `DB` وقاعدة `yarehman-db`.
- R2 Bucket: الاسم `IMAGES` والحاوية `yarehman-images`.

## 2) اربط المستودع

ارفع محتويات هذا المجلد إلى GitHub. إعدادات Pages:
- Framework preset: None
- Build command: اتركه فارغاً
- Build output directory: `public`

احتفظ بمجلد `functions` وملف `wrangler.toml` ومجلد `migrations` في جذر المستودع؛ لا تضعها داخل `public`.

## 3) إعداد D1

ثبّت Wrangler على جهازك أو استخدم Cloudflare Workers Builds، ثم من مجلد المشروع نفّذ:

```bash
npx wrangler login
npx wrangler d1 create yarehman-db
```

انسخ `database_id` الذي يظهر وضعه مكان `REPLACE_WITH_D1_DATABASE_ID` في `wrangler.toml`، ثم اربط D1 من لوحة Pages أيضاً.

طبّق الجداول:

```bash
npx wrangler d1 execute yarehman-db --remote --file=migrations/0001_init.sql
```

## 4) أسرار المدير والجلسات

من إعدادات مشروع Pages > Settings > Variables and Secrets أضف الأسرار التالية (Production، وPreview إذا احتجت):

- `INITIAL_ADMIN_USERNAME` = `IMX`
- `INITIAL_ADMIN_PASSWORD` = `IMXTikTok77@` (أدخلها يدوياً كـ Secret في Cloudflare فقط، ولا تضعها في ملفات المشروع أو GitHub).
- `SESSION_SECRET` = قيمة عشوائية طويلة لا تقل عن 32 بايت.

يمكن توليد سر عشوائي في Windows PowerShell:

```powershell
[Convert]::ToBase64String([Security.Cryptography.RandomNumberGenerator]::GetBytes(48))
```

بعد نشر الموقع افتح `/admin.html` واضغط «إنشاء حساب المدير لأول مرة» مرة واحدة، ثم سجّل الدخول. مسار الإعداد يرفض إنشاء مدير آخر إذا كان هناك مدير موجود.

**مهم:** اسم المستخدم الأول `IMX` وكلمة المرور `IMXTikTok77@`. أدخل كلمة المرور يدوياً في Cloudflare كـ Secret باسم `INITIAL_ADMIN_PASSWORD` فقط؛ لا تحفظها في GitHub أو ملفات ZIP. تُحوّل إلى تجزئة PBKDF2 داخل قاعدة D1 عند إنشاء المدير لأول مرة. هذه البيانات ظهرت في المحادثة، لذا غيّر كلمة المرور بعد الإعداد عبر إجراء آمن قبل الإطلاق التجاري.

## 5) الصور

الشعار الحالي موجود في `public/logo.png`. صور المنتجات يمكن إدخال روابطها في شاشة المنتجات. نقطة API لرفع الملفات إلى R2 هي `POST /api/upload` وتقبل multipart field باسم `file` (حد 5MB) وتتطلب صلاحية مدير المنتجات. ربط واجهة رفع الصور داخل لوحة الإدارة يحتاج استكمالاً منفصلاً.

## 6) اختبار بعد النشر

- افتح `/api/health` ويجب أن يرجع `{ "ok": true }`.
- نفّذ تهيئة المدير من `/admin.html`.
- أضف منطقة توصيل من لوحة الإدارة قبل استقبال الطلبات.
- أضف قسماً ومنتجاً، ثم جرّب الطلب.
- راجع الطلب وغيّر حالته من لوحة الإدارة.

## ملاحظات صريحة قبل التشغيل التجاري

هذا إصدار تشغيل أولي فعلي بقاعدة بيانات وواجهات API، لكنه ليس شهادة جاهزية إنتاجية نهائية. يلزم قبل استقبال أموال أو بيانات عملاء حقيقية: اختبار شامل على حساب Cloudflare الخاص بك، تفعيل قيود معدل محاولات الدخول، إضافة CAPTCHA/حماية من الإساءة، سياسة خصوصية وشروط بيع، بريد/رسائل تأكيد، نسخ احتياطي دوري لـ D1، واجهة تسجيل/دخول العملاء، شاشة رفع الصور وتحرير/حذف كل أنواع المحتوى، ومراجعة أمنية مستقلة. الدفع الإلكتروني غير مدمج؛ المتاح في هذا الإصدار هو الدفع عند الاستلام.

لا يتضمن المتجر خيار «نسيت كلمة المرور» أو استعادة كلمة المرور للعملاء، حسب طلب صاحب المتجر.
